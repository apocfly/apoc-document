# APOC 语音数据交换协议 版本一

## 1. 总则

- 语音服务采用双通道架构：控制通道+语音通道，并支持TCP语音回退通道。
- 服务端监听三个固定端口：2300为控制通道（TCP信令），2301为语音通道（UDP语音），2302为TCP语音通道。
- 控制通道使用TLS加密传输；语音通道与TCP语音通道不加密。
- 控制通道使用JSON文本，UTF-8编码，无BOM，每条消息独占一行并以 `\n` 结尾。
- 语音通道使用二进制编码，所有多字节字段统一使用大端序。
- 所有字段采用snake_case命名。
- 时间戳统一使用Unix毫秒级时间戳，时区固定为UTC。
- 同一时间同一账户只允许拥有一个活跃语音会话，若同一账户试图建立第二个控制连接，则拒绝新连接建立。
- 音频编码统一为Opus，编码参数由服务端在欢迎包中下发。
- 当UDP不可用时，客户端可申请将语音通道回退至TCP传输。
- 结构示例中的注释仅为文档书写便利，实际数据包中不得包含注释内容。

## 2. 名词定义与数据约定

### 2.1 语音服务器

实现本协议所有内容并作为服务端提供接入服务的软件

### 2.2 语音客户端

实现本协议所有或者部分内容并作为客户端连入语音服务的软件或网页

### 2.3 控制通道

使用TLS加密的TCP长连接，承载登录、登出、频道控制、文本消息、心跳等信令数据

### 2.4 语音通道

使用UDP承载实时语音数据，每一份UDP数据报携带一个Opus音频帧；UDP不可用时可通过TCP语音回退通道承载

### 2.5 通话频道

以频率为标识的虚拟空间，同一频率上的客户端可互相收发语音

### 2.6 频率

特指飞行员与管制员通讯使用的无线电频率，单位统一为Hz，整数类型。如122.8MHz写作122800000

### 2.7 发射机

客户端上独立的音频收发设备，发射机ID为客户端自行选择的任意非负整数，用于区分同一客户端上的多个发射机。
飞行员通常使用0与1分别对应COM1与COM2；管制员可为每个管制频率分配一个发射机。
发射机ID为无符号8位字段，取值为0~255。同一客户端可同时注册多个发射机

### 2.8 接收标志

布尔值，表示该发射机当前是否开启接收。接收标志为false时，服务端不会向其转发语音

### 2.9 管制员与飞行员

以管制员身份连接至网络的用户称为管制员，以飞行员身份连接至网络的用户称为飞行员。服务端根据其FSD连接身份区分二者

### 2.10 帧序号

用于语音流的丢包检测与乱序排序

### 2.11 采样时间戳

用于客户端建立抖动缓冲与播放节奏

### 2.12 特殊频率

UNICOM频率为122800000，EMERGENCY频率为121500000。二者不得作为管制员的主用频率；UNICOM与EMERGENCY频率均不得作为频率合并组的成员频率

### 2.13 会话密钥

服务端在登录时为每个会话生成的32字节随机密钥，用于计算语音数据包认证标签

### 2.14 认证标签

基于会话密钥对语音数据包计算的MAC摘要，用于防止冒充与篡改

### 2.15 TCP回退

当UDP不可用时，将语音通道切换至TCP传输的机制

### 2.16 频率合并

将多个频率合并为一个虚拟频道的功能，仅管制员可使用。
合并组内的频率被视为同一频道，任一成员频率上的客户端可以听到其他成员频率上的语音，管制员可同时收发全部成员频率的语音。
例如将118.1与118.2合并后，两频率上的飞行员互相听得见，形同共用一个更大的频率。

## 3. 连接流程

### 3.1 登录

1. 客户端建立到控制通道的TLS加密TCP连接，并校验服务端证书。
2. 客户端发送登录包，`payload.token` 携带JWT登录令牌。
3. 服务端校验令牌。若校验失败，服务端发送错误包并关闭连接。
4. 若同一账户已有活跃会话，服务端发送错误包并关闭新连接。
5. 校验通过后，服务端发送欢迎包，携带会话密钥与音频编码参数。
6. 除登录包外，客户端不得在登录完成前发送其他控制包，否则服务端发送错误包（错误码10013）并关闭连接。

### 3.2 心跳

- 服务端在超时时间内未从客户端收到任何控制包，则视为超时并关闭连接。
- 客户端应在超时时间的一半之内至少发送一次Ping包，服务端以Pong包响应。
- 语音通道的数据不会刷新控制通道的存活状态，客户端不得仅靠发送语音维持连接。

### 3.3 登出与断开

- 客户端或服务端任一方可发送登出包主动结束会话，发送后应关闭TCP连接。
- 服务端因异常断开连接时，应先向客户端发送错误包或登出包说明原因。

## 4. 控制数据包

### 4.1 基础控制包结构

所有控制包共享如下结构：

```json5
{
  // 协议版本号
  "protocol": 1,
  // 数据包类型
  "type": 0,
  // 客户端ID
  "cid": 2352,
  // 呼号
  "callsign": "CES2352",
  // 发射机ID，仅频道控制类数据包有效
  "transmitter": 0,
  // Unix毫秒时间戳
  "timestamp": 1785246789440,
  // 数据包负载
  "payload": null,
}
```

- TCP连接建立后，客户端发送的第一个控制包必须是登录包，否则服务端发送错误包并关闭连接。
- 客户端发送的控制包中，`cid` 与 `callsign` 可省略，服务端一律以登录时的身份为准；若填写且与登录身份不一致，服务端丢弃该包并发送错误包。
- 服务端发送的控制包中，`cid` 与 `callsign` 为接收客户端的身份。
- 若服务端发现客户端发送的控制包负载过大，则丢弃该包并发送错误包。

### 4.2 数据包类型

type定义为16位整数，前八位代表数据包分类，后八位为每个分类下的数据包ID

#### 4.2.1 系统数据包

##### 4.2.1.1 错误包(type=0)

错误包仅允许从服务端发往客户端，从客户端发来的错误包应该被服务器忽略

```json5
{
  "protocol": 1,
  "type": 0,
  "cid": 2352,
  "callsign": "CES2352",
  "transmitter": 0,
  "timestamp": 1785246789440,
  "payload": {
    // 错误码
    "error_code": 10000,
    // 错误详情
    "error_message": "未知错误"
  }
}
```

| 错误码   | 描述             |
|:------|:---------------|
| 10000 | 未知错误           |
| 10001 | 系统错误           |
| 10002 | 认证失败           |
| 10003 | 客户端已在线         |
| 10004 | 无FSD连接         |
| 10005 | 存在多个FSD连接      |
| 10006 | 达到数据包速率限制      |
| 10007 | 数据包格式错误        |
| 10008 | 无效频率           |
| 10009 | 频率不匹配          |
| 10010 | 数据包过大          |
| 10011 | 未知消息类型         |
| 10012 | 未登录            |
| 10013 | 权限不足，仅管制员可用此功能 |

##### 4.2.1.2 欢迎包(type=1)

欢迎包由服务端在客户端登录成功后发送，用于告知会话信息、会话密钥与语音编码参数

```json5
{
  "protocol": 1,
  "type": 1,
  "cid": 2352,
  "callsign": "CES2352",
  "transmitter": 0,
  "timestamp": 1785246789440,
  "payload": {
    // 服务端支持的协议版本号
    "protocol_version": 1,
    // pilot或者atc
    "client_type": "pilot",
    // 管制员当前主用频率，单位Hz，飞行员为null
    "frequency": null,
    // 32字节随机会话密钥，Base64编码，用于计算语音数据包认证标签
    "session_key": "aGVsbG8...",
    "audio": {
      // 语音编码
      "codec": "opus",
      // 采样率
      "sample_rate": 48000,
      // 声道数
      "channel": 1,
      // 单帧时长，单位ms
      "frame_time": 20
    }
  }
}
```

##### 4.2.1.3 登录包(type=2)

登录包由客户端在建立TCP连接后首先发送，用于向服务端提供登录令牌完成鉴权

```json5
{
  "protocol": 1,
  "type": 2,
  "timestamp": 1785246789440,
  "payload": {
    // JWT登录令牌
    "token": "eyJhbGciOiJIUzI1NiIs...",
    // 客户端名称，可选
    "client_name": "AudioClient 1.0.0"
  }
}
```

##### 4.2.1.4 登出包(type=3)

登出包用于任一方主动结束会话，可携带结束原因

```json5
{
  "protocol": 1,
  "type": 3,
  "timestamp": 1785246789440,
  "payload": {
    // 登出原因
    "reason": "客户端主动登出"
  }
}
```

##### 4.2.1.5 Ping包(type=4)

Ping包允许客户端或者服务端检测对方是否在线，payload中的 `seq` 是一个随机的三十二位整数值，由发送方生成

```json5
{
  "protocol": 1,
  "type": 4,
  "timestamp": 1785246789440,
  "payload": {
    "seq": 7
  }
}
```

##### 4.2.1.6 Pong包(type=5)

Pong包用于响应Ping包，`seq` 原样回填

```json5
{
  "protocol": 1,
  "type": 5,
  "timestamp": 1785246789440,
  "payload": {
    "seq": 7
  }
}
```

##### 4.2.1.7 回退请求包(type=6)

回退请求包用于申请开启或者关闭TCP回退通道

```json5
{
  "protocol": 1,
  "type": 6,
  "timestamp": 1785246789440,
  "payload": {
    // 是否启用TCP回退
    "enable": true,
    // 申请回退的原因，可选
    "reason": ""
  }
}
```

##### 4.2.1.8 回退响应包(type=7)

回退响应包用于同意开启或者关闭TCP回退通道

```json5
{
  "protocol": 1,
  "type": 6,
  "timestamp": 1785246789440,
  "payload": {
    // 是否同意TCP回退
    "approve": true,
    // 若拒绝，原因
    "reason": ""
  }
}
```

#### 4.2.2 频道控制数据包

##### 4.2.2.1 频道切换包(type=256)

频道切换包由客户端发送，用于将指定发射机切换到目标频率并设置接收标志
服务端收到后应将该发射机从原频道移除并加入新频道，随后回执一条切换确认包告知切换结果
同一客户端可发送使用不同的`transmitter`的频道切换包注册多个发射机，分别工作在不同频率上

```json5
{
  "protocol": 1,
  "type": 256,
  "transmitter": 0,
  "timestamp": 1785246789440,
  "payload": {
    // 目标频率，单位Hz
    "frequency": 122800000,
    // 接收标志
    "receive": true
  }
}
```

##### 4.2.2.2 接收标志包(type=257)

接收标志包由客户端发送，用于仅修改指定发射机的接收标志而不改变频率
`payload`中的 `frequency` 必须与该发射机已注册频率一致，否则服务端丢弃该包并发送错误包（错误码10009）

```json5
{
  "protocol": 1,
  "type": 257,
  "transmitter": 0,
  "timestamp": 1785246789440,
  "payload": {
    // 发射机当前频率，单位Hz
    "frequency": 122800000,
    // 接收标志
    "receive": true
  }
}
```

##### 4.2.3.3 切换确认包(type=258)

切换确认包用于服务器确认客户端的判断和标志位切换

```json5
{
  "protocol": 1,
  "type": 258,
  "callsign": "SERVER",
  "transmitter": 0,
  "timestamp": 1785246789440,
  "payload": {
    // 发射机当前频率，单位Hz
    "frequency": 122800000,
    // 接收标志
    "receive": true
  }
}
```

##### 4.2.2.4 频率合并包(type=259)

频率合并包由管制员发送，用于声明或取消频率合并，将多个频率合并为一个虚拟频道

- 仅管制员可发送，飞行员发送时服务端丢弃该包并发送错误包（错误码10014）。
- `frequency` 为合并组主频率，`coupled_frequencies` 为成员频率列表；所有频率必须为该管制员已通过频道切换包注册的发射机频率，否则服务端丢弃该包并发送错误包。
- 合并组内的主频率与成员频率均不得为UNICOM或EMERGENCY频率。
- `enable=true` 时，服务端将 `frequency` 与 `coupled_frequencies` 合并为该管制员的合并组，此时 `coupled_frequencies` 不得为空；
  `enable=false` 时，取消该管制员的全部合并声明。
- 若不同管制员声明的合并组存在交集频率，服务端按传递闭包将这些频率合并为同一虚拟频道，以保证路由一致性。

```json5
{
  "protocol": 1,
  "type": 259,
  "timestamp": 1785246789440,
  "payload": {
    // true=开启合并，false=取消合并
    "enable": true,
    // 合并组主频率，单位Hz
    "frequency": 118100000,
    // 合并组成员频率列表，单位Hz
    "coupled_frequencies": [
      118200000
    ]
  }
}
```

## 5. 语音数据包

### 5.1 数据包结构

语音数据包通过UDP传输，一份数据报携带一个Opus音频帧，所有字段使用大端序：

| 偏移     | 长度 | 类型    | 字段           | 说明            |
|:-------|:---|:------|:-------------|:--------------|
| 0      | 1  | u8    | version      | 协议版本号，固定为0x01 |
| 1      | 1  | u8    | type         | 数据包类型，固定为0x00 |
| 2      | 4  | u32be | seq          | 帧序号           |
| 6      | 4  | u32be | timestamp    | 采样时间戳，Unix毫秒  |
| 10     | 4  | i32be | cid          | 客户端ID         |
| 14     | 1  | u8    | transmitter  | 发射机ID         |
| 15     | 4  | i32be | frequency    | 频率，单位Hz       |
| 19     | 1  | u8    | callsign_len | 呼号长度          |
| 20     | L  | -     | callsign     | 呼号            |
| 20+L   | N  | -     | payload      | Opus音频帧       |
| 20+L+N | 8  | u8    | auth         | 认证标签          |

呼号采用长度前缀编码，`callsign_len`为呼号字节长度，不得超过127。
固定头长度为20字节，随呼号变化。数据报由固定头、callsign、payload与末尾8字节认证标签组成。
UDP数据报自带长度边界，不再使用长度前缀或结尾分隔符，接收方依据数据报长度确定`payload`长度
`payload` 长度 = 数据报长度 - 20 - 呼号长度 - 8。

### 5.2 会话密钥与认证标签

- 会话密钥由服务端在登录时生成，为32字节随机值，通过欢迎包的 `session_key` 字段下发。同一会话的客户端与服务端各持一份。
- 认证标签计算方式：`auth = HMAC-SHA256(session_key, 数据报中除末尾8字节认证标签外的全部字节)`，取结果前8字节。
- 服务端收到语音数据包后，使用该会话的会话密钥重新计算认证标签并与包内认证标签比对，不一致则视为伪造，丢弃该包并记录错误日志。
- 客户端应使用相同方式校验服务端发来的语音数据包。
- `seq` 可用于检测重复帧。

### 5.3 帧序号与采样时间戳

- `seq` 按 `(cid, transmitter)` 音频流递增，流起始值任意，之后每帧加1，超出u32范围后环绕。客户端据此检测丢包与乱序。
- `timestamp` 为该帧采样时刻的Unix毫秒时间戳，由发送方填充。客户端据此建立抖动缓冲并控制播放节奏。
- 服务端转发语音包时，保留头部与 `payload` 原样，不得改写 `seq` 与 `timestamp`，以支持接收方端到端重建音频流。

### 5.4 服务端转发行为

服务端收到语音数据包后，首先校验认证标签，然后以 `cid` 查找客户端，并校验 `transmitter` 与 `frequency` 与已注册状态一致，不一致则丢弃该包。
同时必须校验包内 `callsign` 与该 `cid` 登录时的呼号一致，若不一致则视为冒充，丢弃该包并记录错误日志。
校验通过后，服务端将该包转发给发送方所在频道内的其他客户端；若发送方所在频率属于某个合并组，则转发目标为该合并组内全部成员频率上的客户端。
目标客户端须同时满足以下条件：

1. 已注册UDP地址（或已建立TCP回退通道）；
2. 接收标志为true；
3. 与发送方距离处于语音通讯范围内，或在当前频道（合并组）管制员的覆盖范围内。

服务端不得修改 `payload` 内容。

## 6. TCP回退

### 6.1 触发与协商

- 客户端检测到UDP不可用时，通过控制通道发送回退请求包申请将语音通道切换至TCP。
- 服务端回复回退请求包。
- 客户端可随时发送回退请求包关闭TCP回退并切回UDP。

### 6.2 音频回退连接

- 协商通过后，客户端建立到TCP语音回退端口的TCP连接，并发送登录包携带同一JWT令牌。
- 服务端根据连接端口识别其为语音回退通道，并校验该账户已有活跃语音会话且已开启TCP回退，通过后将该连接绑定为该会话的音频通道，不视为重复登录。
- 音频回退连接建立后，客户端与服务端通过该连接双向传输语音帧，帧格式见6.3。
- 服务端向其他客户端转发语音时，按接收方当前激活的传输通道投递。

### 6.3 帧格式

TCP是字节流，每个语音帧末尾为固定的0x2352，每个音频帧是5.1定义的完整语音数据包：

```
[packet...][0x2352][packet...][0x2352][packet...][0x2352]
```

### 6.4 切换

- 回退协商期间，服务端应同时支持UDP与TCP回退两种通道，避免丢音。
- 客户端在切换完成前应继续发送语音数据包，防止切换窗口期丢包。

## 7. 传输加密

### 7.1 加密范围

- 仅控制通道使用TLS加密，TLS握手完成前客户端不得发送任何协议数据。
- 语音通道与TCP语音回退通道不加密，语音数据视为公开信息。

### 7.2 证书

- 服务端使用自签名证书，证书有效期建议设为长期，证书必须覆盖客户端连接所用的主机名或IP地址。
- 客户端内嵌服务端公钥，TLS握手时校验服务端公钥与内嵌值一致，即公钥固定。
- 客户端不依赖系统信任库与公共CA，即使CA被攻破也不会影响本协议的安全性。
- 建议使用TLS 1.2及以上版本。
